Your personal access token

Databricks Apps cannot call the Clusters API as you (there is no user-authorization scope for it), so the cluster list and its events are read with your own token. You see exactly the clusters you have a permission on.

Create one in Databricks: your avatar → Settings → Developer → Access tokens → Generate. A short lifetime (for example 30 days) is enough.
  • It is checked against your sign-in: a token that belongs to someone else is refused.
  • It is sealed and kept only in an HttpOnly cookie in this browser (max 30 days). Page scripts cannot read it; the app never stores or logs it. Inside App-ception the sealing key lives only in this app's memory, so other apps in the catalog cannot read it, and you re-enter the token after the app restarts.
  • It is used only to read clusters, cluster events and node types. Everything else runs on your normal sign-in.
